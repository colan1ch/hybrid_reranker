## Этап 1. Решения и доступы (16–20 октября)

### 1.1. Решить четыре вопроса — вместе

Это нужно сделать **до** первого запуска: от ответов зависят настройки в `config.toml`, а менять их потом значит начинать заново.

1. **Откуда брать вопросы.**
   - Сейчас порог подбирается на вопросах из одной части HotpotQA (лёгкие и трудные вперемешку), а проверяется на другой (только трудные). Порог может «не переехать».
   - Вариант: брать обе выборки из одного набора, `sample_source = "beir_test"`.
   - Совет: брать из одного набора.
2. **Сколько проверочных вопросов: 100 или 200.**
   - На них подбирается порог и учится мини-модель. 100 мало: у Bacellar было около 400.
   - 200 стоит примерно на 1,2 дня лимита больше.
   - Совет: 200, если по срокам успеваем.
3. **Что считаем успехом.** Записать числа заранее, до результатов, иначе выводы будут подгоняться. Например:
   - «каскад теряет не больше 0,02 nDCG@10 по сравнению с „всегда дорогая“ и вызывает её меньше чем в половине вопросов»;
   - «правило заметно лучше монетки».
4. **Научные данные (SciFact).** Добавляют 2–3 дня работы и риск не уложиться в 6 страниц. Совет: не брать, упомянуть как дальнейшую работу.

Готово, когда: ответы записаны в раздел 0 файла `RESULTS_PLAN.md`, а в `config.toml` выставлены `validation_size` и `sample_source`.

### 1.2. Видеокарта — Коля

- Нужна для поиска по 5,2 млн текстов. На процессоре это около 3 суток, на видеокарте — несколько часов.
- Варианты: кафедра или университет, Google Colab, Kaggle (обе бесплатные с ограничением по времени сессии).
- Нужно около 30 ГБ диска: кэш эмбеддингов около 16 ГБ плюс корпус.
- Поиск можно прерывать: готовые порции сохраняются, и при повторном запуске он продолжает с места остановки.
- В `config.toml` выставить `device = "cuda"`.

Готово, когда: есть машина с видеокартой, где запускается `rerank --help`.

### 1.3. Ключ Groq — Дима

1. Зайти в консоль Groq и убедиться, что тариф **бесплатный** и **карта не привязана**.
   Если бесплатный доступ требует карту, ничего не запускаем, а обсуждаем замену сервиса.
2. Сверить лимиты в консоли с `config.toml`: 30 запросов и 8 тысяч токенов в минуту, 1000 запросов и 200 тысяч токенов в сутки, отдельно на каждую модель.
3. Положить ключ в `.env` на той машине, где будут идти запуски (см. этап 3). В репозиторий ключ не коммитить.

Готово, когда: ключ работает и лимиты сверены.

## Этап 2. Поиск и BERT (20–24 октября) — Коля

Все команды из корня репозитория, ветка `dev`:

```bash
pip install -e ".[dev,plots]"
pytest -q                 # должно быть всё зелёное
rerank prepare            # выбирает вопросы
rerank retrieve           # поиск, на видеокарте
rerank run --split validation --method dense
rerank run --split validation --method bert
rerank run --split test --method dense
rerank run --split test --method bert
rerank estimate           # сколько дней лимита понадобится, по реальным текстам
```

- `retrieve` создаёт `candidates.jsonl` с 20 найденными текстами на каждый вопрос. Дальше видеокарта не нужна.
- Всю папку прогона (`runs/main/`) и папку `data/` переносим на машину для этапа 3, если это другая машина.

Готово, когда: есть `candidates.jsonl`, `*.dense.jsonl`, `*.bert.jsonl` для обеих выборок, а `rerank estimate` показал срок.

## Этап 3. Дорогая нейросеть и ответы (24 октября – 5 ноября) — Коля

Видеокарта здесь не нужна, хватит обычного ноутбука, который может работать долго.

**Важно:** все запуски с API делать **на одной машине** и не удалять `data/api.jsonl`. В этом файле кэш ответов нейросети. Каскады отправляют те же запросы и берут ответы из кэша бесплатно. Без кэша они потратят лимит заново.

```bash
rerank run --split validation --method llm --allow-api   # ~1,2 дня лимита на 100 вопросов
rerank tune                                              # подбор порога, без API
rerank gate                                              # мини-модель, без API
rerank run --split test --method llm --allow-api         # ~3,6 дня на 300 вопросов
rerank run --split test --method all --answers --allow-api
```

- Флаг `--allow-api` означает: «я проверил, что тариф бесплатный и карты нет».
- Когда кончается суточный лимит, команда сама останавливается. На следующий день запускается **та же** команда, и она продолжает с места остановки.
- Если `rerank gate` пишет, что мало примеров, где дорогая модель помогла, это тоже результат. Записать долю и обсудить вместе.
- Отдельная проверка порядка текстов: в новой папке прогона с `llm_input_order = "bert"` прогнать дорогую модель на 30–50 проверочных вопросах (подробности в `README.md`). Это нужно, чтобы убедиться, что «всегда дорогая» не занижена.

Готово, когда: `rerank evaluate --split test --method all --answers` проходит без сообщений о недостающих данных.

## Этап 4. Текст без результатов (параллельно с этапом 3) — Дима

Эти части не зависят от чисел, их можно писать сразу.

1. **Шаблон.** Скачать шаблон IEEE в две колонки (LaTeX или Word, смотреть требования конференции). Проверить, сколько места занимает пустой шаблон с заголовками.
2. **Введение** (около 0,5 страницы).
   - Задача: система отвечает на вопросы по Википедии.
   - Проблема: дорогая модель ранжирует лучше, но каждый вызов тратит лимит и время.
   - Наш вопрос и вклад: проверка с монеткой и оракулом. Новым методом не называем.
3. **Обзор литературы** (около 0,5–0,7 страницы). Список работ есть в `PLAN_ADDITIONS.md`:
   - Bacellar (вратарь, и правило «разрыв» как его базовый вариант);
   - ARDS, Genc и др., Dabod и др., BalanceRAG, AcuRank;
   - FrugalGPT, RankGPT, CoRank, Ni и др.;
   - каскадное ранжирование Wang, Lin, Metzler 2011.

   Главный абзац: чем мы отличаемся от Bacellar (сигнал от BERT, а не от поисковика; запасной порядок BERT; полный корпус; итоговые ответы и реальные токены).
4. **Метод и постановка эксперимента** (около 1 страницы).
   - Модели, данные, 20 кандидатов, правило порога, мини-модель, контроли.
   - Метрики: nDCG@10, «оба нужных текста в топ-5», EM, F1, токены, доля вызовов.
   - Две оговорки обязательно:
     - порог мини-модели подбирается по отложенным частям проверки, а применяется модель, обученная на всех проверочных вопросах;
     - оракул вызывает дорогую модель ровно столько раз, сколько правило, поэтому это не «вызов только там, где поможет».
5. **Рисунок 1 (схема каскада).** Вопрос → поиск (20 текстов) → BERT → ромб «разрыв ≤ порога?» → дорогая модель или порядок BERT → генератор ответа. Чёрно-белый, в одну колонку.
6. **Правила конференции.** Как указывать использование ИИ при подготовке работы, требования к анонимности, взнос.

Готово, когда: введение, обзор, метод и рисунок 1 вставлены в шаблон. Пусть пока это 2,5–3 страницы.

## Этап 5. Результаты и выводы (5–15 ноября) — вместе

1. **Коля** запускает анализ (всё без API):
   ```bash
   rerank controls --split test
   rerank resplit
   rerank report --split test
   ```
   Получаются `report/test/figure_2.pdf`, `table_1.tex`, `table_2.tex` и `controls/test.cases.csv`.
2. **Вместе** смотрим рисунок 2 и отвечаем на три вопроса:
   - лучше ли правило монетки;
   - насколько оно далеко от оракула;
   - мини-модель лучше правила при **равном** числе вызовов или нет (это в таблице 2, блок «equal budget»).
3. **Разбор ошибок.** Открыть `controls/test.cases.csv`: первыми идут вопросы, где правило ошиблось. Каждый читает по 15 и записывает в одну строку, почему так вышло (например: «оба текста похожи по теме», «вопрос на сравнение», «дорогая модель ошиблась сама»). Потом сводим в 3–4 типа ошибок.
4. **Пишем** «Результаты» (около 1 страницы) и «Обсуждение и ограничения» (около 0,5 страницы).
   - Честно, по заранее записанному критерию успеха.
   - Если результат отрицательный, строим текст вокруг «почему не работает», с разбором ошибок.
   - Ограничения: один набор данных, бесплатные лимиты, размер выборки.
5. **Аннотация и заключение** — в самом конце, когда всё понятно.

Готово, когда: черновик целиком в шаблоне.

## Этап 6. Вычитка и подача (15–27 ноября) — Дима, Коля проверяет

1. Не больше 6 страниц вместе с литературой. Если не влезает, сначала убираем рисунок 1, потом сокращаем обзор.
2. Анонимизация:
   - в тексте нет имён и организации;
   - в PDF нет автора в свойствах файла;
   - вместо ссылки на наш GitHub — анонимная копия кода без истории коммитов, без имён и без `AGENT_REPORT.md`.
3. Проверить, что все числа в тексте совпадают с `table_1.csv` и `table_2.csv`, и нигде нет «МАКЕТ».
4. Слова «значимо», «лучше», «новый метод» — только там, где это показывают интервалы и данные.
5. Указать использование ИИ, если этого требуют правила.
6. Заполнить форму: секция, название, авторы. Отправить. Проверить, что пришло подтверждение.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Groq требует карту | Ничего не запускать, обсудить другой бесплатный сервис или модель |
| Нет видеокарты | Поиск на процессоре, около 3 суток; запустить как можно раньше |
| Лимит кончается раньше, чем ожидали | Запуски сами продолжатся на следующий день; при сильном отставании сократить тест до 200 вопросов (решить вместе) |
| Мини-модель не учится (мало примеров, где дорогая помогает) | Это результат: записать долю и обсудить. `rerank report` всё равно соберёт рисунок и таблицы, просто без строк мини-модели. При необходимости взять 200 проверочных вопросов |
| Правило не лучше монетки | Тоже результат: статья про то, почему простой сигнал не работает |
| Не влезаем в 6 страниц | Убрать рисунок 1, сжать обзор, перенести детали в анонимный репозиторий |
