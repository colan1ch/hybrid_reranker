### К3. Дорогая модель и ответы (вс 18 – пт 23)

**Важно:** все запуски с API делать **на одной машине** и не удалять `data/api.jsonl`.
В нём кэш: каскады отправляют те же запросы и получают ответы бесплатно. Без кэша они потратят лимит заново.

У 120B и 20B лимиты **отдельные**, поэтому два терминала работают **одновременно**.

**Терминал 1 — дорогая модель (120B):**
```bash
rerank run --split validation --method llm --allow-api   # ~1,2 дня
# после К4:
rerank run --split test --method llm --allow-api         # ~3,6 дня
```

**Терминал 2 — генератор ответов (20B)**, можно начинать сразу после К2:
```bash
rerank run --split test --method bert --answers --allow-api
rerank run --split test --method dense --answers --allow-api
# когда терминал 1 закончит тест:
rerank run --split test --method all --answers --allow-api
```

- Флаг `--allow-api` означает: «я проверил, что тариф бесплатный и карты нет» (Д1).
- Когда суточный лимит кончается, команда останавливается сама. Через несколько часов запускается **та же** команда и продолжает с места остановки.
- Раз в день проверять, что запуски идут: число строк в `runs/main/test.llm.jsonl` растёт.
- Если что-то падает с ошибкой, присылать текст ошибки Claude.

Готово, когда: `rerank evaluate --split test --method all --answers` проходит без сообщений о недостающих данных.

### К5. Проверка порядка текстов (чт 22 – пт 23, когда терминал 1 освободится)

Проверяем, не занижает ли результат «всегда дорогая» то, что модели сейчас дают тексты в порядке поиска, а не BERT.

- порог мини-модели подбирается по отложенным частям проверки, а применяется модель, обученная на всех проверочных вопросах;
- оракул вызывает дорогую модель ровно столько раз, сколько правило, поэтому это не «вызов только там, где поможет».
