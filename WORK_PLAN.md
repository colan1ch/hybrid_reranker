# План работ до подачи статьи (срок: 28 октября)

**Датасет:** BEIR SciFact. **Выборки:** проверочные 200 утверждений из BEIR `train`, тестовые все 300 из BEIR `test` (решения в `RESULTS_PLAN.md`, раздел 0).
**Узкое место:** суточный бесплатный лимит Groq на ключ, около 45 запросов к 120B в сутки (один запрос ≈ 4,4 тыс. токенов).
Поэтому каждый запускает 120B на **своём** бесплатном аккаунте, а вопросы делятся пополам флагом `--part`.

## Задачи Коли

### К1. Подготовка, поиск, BERT и раздача папки (пн 19)

```bash
git checkout dev && git pull        # после слияния веток
pip install -e ".[dev,plots]"
pytest -q
rerank prepare
rerank retrieve                    # около получаса на процессоре
rerank run --split validation --method dense
rerank run --split validation --method bert
rerank run --split test --method dense
rerank run --split test --method bert
```

Поиск должен считаться на **той же машине**, где Коля считал прежний SciFact (эмбеддинги корпуса уже в `data/embeddings`): на другом железе кандидаты могут слегка отличиться, и ответы 120B из кэша не подойдут.
Потом **запаковать папку `runs/final/` целиком** и отправить Диме. `data/` отправлять не нужно, кроме `data/api.jsonl` (см. Д2).

Готово, когда: у Димы есть та же папка `runs/final/`.

### К2. Своя половина, 120B (вт 20 – пт 23)

Со **своим** ключом Groq. Сначала проверочные, потом тестовые:

```bash
rerank run --split validation --method llm --part 1/2 --allow-api   # 100 новых, около 2,2 суток
rerank run --split test --method llm --part 1/2 --allow-api         # 50 новых, 100 из кэша, около 1,1 суток
```

Когда суточный лимит кончается, команда сама останавливается (код 75). Через несколько часов запускается **та же** команда и продолжает с места остановки. Для ночных запусков есть цикл в `README.md`.

### К3. Слияние, пороги, таблицы (чт 22 – сб 24)

Когда Дима пришлёт свою папку `runs/final/` и `data/api.jsonl`, положить их, например, в `dima/`.

```bash
rerank merge --from dima/runs/final --api dima/data/api.jsonl
rerank tune                                                  # после слияния проверочных; порог больше не трогаем
rerank gate
rerank run --split test --method all --allow-api              # почти без запросов: всё из кэша
rerank evaluate --split test --method all
rerank controls --split test
rerank resplit --calibration-size 200
rerank report --split test
```

`merge` сам перенесёт `thresholds.json` и `gate.json`. Получаются `report/test/figure_2.pdf`, `table_1.tex`, `table_2.tex` и `controls/test.cases.csv`. Отправить Диме и Claude.

### К4. Проверка порядка текстов (вс 25, если остался лимит)

Проверяем, не занижает ли результат «всегда дорогая» то, что модели дают тексты в порядке поиска, а не BERT.

1. Скопировать `runs/final/` в `runs/order/`, взять `config.toml`, сохранить как `order.toml`, поменять `run_dir = "runs/order"`, добавить `llm_input_order = "bert"`.
2. В `runs/order/` оставить `candidates.jsonl`, `validation.jsonl`, `validation.bert.jsonl`; в `validation.jsonl` первые 50 вопросов.
3. `rerank --config order.toml run --split validation --method llm --allow-api` (около 1,1 суток), затем `evaluate`.
4. Сравнить nDCG@10 с основным прогоном на тех же 50 вопросах.

### К5. Сверка чисел (пн 26)

Каждое число в тексте статьи сверить с `table_1.csv` и `table_2.csv`. Нигде не должно быть слова «МАКЕТ».

## Вместе

### В1. Смотрим результаты (сб 24)

По рисунку 2 и таблицам 1–2 отвечаем на четыре вопроса:
- лучше ли правило «разрыв» монетки;

### В2. Разбор ошибок (вс 25)

1. Открыть `controls/test.cases.csv` в Google Таблицах. Первыми идут вопросы, где правило ошиблось (`gap_lost_quality = True`).
2. Добавить столбец «причина». Коля берёт первые 15 строк, Дима следующие 15.
3. Для каждого утверждения прочитать само утверждение, правильные абстракты (`gold_titles`) и первые 5 у BERT и у дорогой модели (`bert_top5`, `llm_top5`). Записать причину из списка или свою:
   - **похожие тексты** — у BERT два первых текста про одно и то же, разрыв маленький, хотя ответ верный;
   - **уверен, но неправ** — разрыв большой, а нужного текста наверху нет;
   - **ошиблась дорогая модель** — она поставила нужные тексты ниже, чем BERT;
   - **сбой** — у дорогой модели был сбой (`llm_failed = True`);
   - **утверждение требует нескольких абстрактов** или **абстракт обрезан до 192 токенов**.
4. Свести в таблицу «причина → сколько вопросов» и выбрать 2–3 примера для текста.

| Проблема | Кто | Что делать |
|---|---|---|
| Groq требует карту | Дима | Ничего не запускать, сразу обсудить замену |
| `merge` пишет, что настройки или вопросы различаются | Коля | Папки разошлись: взять папку Коли из К1 за основу и прислать Claude вывод команды |
