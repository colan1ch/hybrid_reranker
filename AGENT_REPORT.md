## Что сделано

1. **Контроли — `controls.py`, `rerank controls`.**
   Монетка с фиксированным seed и многократным выбором без возвращения; оракул; бюджеты 10/25/50/75/100%;
   правило gap и gate при наличии модели; матрицы 2×3; AUC; сохранённая доля прироста и отношение к оракулу.
   CSV и JSON сохраняются в `run_dir/controls/`. При единственном классе AUC пустой.
   При нулевом знаменателе отношения приростов пустые. Для случайного выбора сохраняются эмпирические веса включения
   вопросов, чтобы таблица результатов использовала те же выборки, что и контроль.

2. **Повторные разбиения — `splits.py`, `rerank resplit`.**
   По умолчанию 100 повторов; seed из конфигурации; размер калибровки из `validation_size`.
   Есть `--calibration-size`, `--source`, `--repeats`. В каждом повторе порог выбирается на калибровочной части
   по допуску и порядку выбора `tune`: токены, доля вызовов, качество. Проверочная часть при выборе не используется.
   Сохраняются id частей, пороги, доли вызовов, разности с полным LLM, медиана, p05–p95, доля нарушений допуска.
   Ни основной `thresholds.json`, ни основной протокол при этом не меняются.

3. **Мини-модель — `gate.py`, `rerank gate`, `cascade_gate`.**
   `FEATURES`: gap 1–2, gap 1–5, std top-10 BERT. Метка — прирост nDCG@10 строго больше `--min-gain`, по умолчанию 0.
   StandardScaler и LogisticRegression обучаются внутри пяти частей StratifiedKFold, без подбора гиперпараметров.
   AUC и порог вычисляются по OOF-предсказаниям. Итоговая модель обучается только на validation, сохраняется в JSON
   с коэффициентами, стандартизацией, id частей, метками протокола и OOF-вероятностями. Test-файлы обучение не читает.
   При менее 10 положительных или 5 отрицательных метках печатаются предупреждение и доля положительных; обучения нет.
   `cascade_gate` читает сохранённые BERT/LLM-результаты и ответы. Не создаёт клиент API и не генерирует отсутствующие ответы.
   Для validation использует OOF-предсказания; пересечение обучающих и test-id отклоняется.

4. **Рисунок и таблицы — `report.py`, `rerank report`.**
   Рисунок 2: четыре линии с разными стилями и маркерами, точки BERT/полного LLM, вертикальная метка замороженного gap-порога;
   PNG и PDF. Таблицы 1–2: CSV и LaTeX; также сохраняется JSON с примечаниями.
   В таблице 1 есть nDCG, оба релевантных документа в top-5, EM/F1, доля вызовов, токены реранкера/генератора,
   отдельные доли сбоев реранкера и генератора; query-bootstrap 95% для nDCG и парных разностей с LLM.
   В таблице 2 — матрицы gap/gate, сохранённая устойчивость gap и AUC. При отсутствии разбиений указан пропущенный шаг.
   Отсутствующие EM/F1 и токены генератора остаются пустыми. Рисунок 1 не создавался, согласно заданию.
   Matplotlib — необязательная зависимость `[plots]`.

5. **Оба дополнительных пункта.**
   `rerank estimate` печатает оценку вызовов, токенов и квотных дней отдельно по моделям; использует лимиты конфигурации,
   ориентир 2400 токенов на вызов 120B и настраиваемую оценку генератора. Это оценка без кэша и повторов, не измерение.
   Команда не создаёт папку прогона.
   `sample_source = "beir_test"` включает две непересекающиеся балансируемые выборки из одного BEIR test в новой пустой папке.
   Источник фиксируется в `sampling.json`. По умолчанию опция выключена; прежний dev/test-протокол сохранён.

## Соглашения и ограничения

- Бюджет означает ровно `floor(n * доля)` вызовов. При равных сигналах сохраняется исходный порядок вопросов.
  Оракул при 100% совпадает с полным LLM, поскольку обязан вызвать его везде, в том числе на вредных вопросах.
- У gate сигнал равен минус вероятности полезного вызова: используется то же сравнение `signal <= threshold`, что у gap.
  При изменении min-gain меняется целевая метка gate; её определение записывается рядом с AUC.
- p05–p95 разбиений и случайного выбора — эмпирический разброс, не доверительный интервал.
  Пересекающиеся повторные разбиения не считаются независимыми проверками.
- Повторные разбиения по умолчанию используют объединение прежних validation/test. Различие их распределений этим не устраняется.
  Устойчивость gate с переобучением на этих частях не оценивалась: test не передавался в обучение gate.
- Полосы вокруг бюджетных кривых не выводятся из разброса одного фиксированного порога; для таких полос нужны отдельные кривые
  на каждом разбиении. Неподтверждённые интервалы не рисуются.
- В рабочей `runs/` не было сохранённых вопросов, BERT/LLM-результатов или thresholds.json. Реальные результаты не создавались;
  входы и замороженные пороги сохраняются неизменными в проверках на искусственных файлах.
- К Groq, Hugging Face и другим внешним API не обращался. Сеть нужна только для операций Git с указанным репозиторием.
  Отправка выполняется обычным `git push origin dev` после `git pull --ff-only origin dev`, без force.
