# Выборочное LLM-реранжирование

Обвязка для эксперимента на BEIR HotpotQA: один dense-поиск top-20, четыре варианта ранжирования и одинаковый генератор ответов. Полные эксперименты пока не проведены.

| Режим | Ранжирование |
| --- | --- |
| `dense` | Порядок `BAAI/bge-base-en-v1.5` |
| `bert` | Все top-20 через `BAAI/bge-reranker-base` |
| `llm` | Все top-20 через GPT-OSS 120B |
| `cascade_gap` | BERT; при малом разрыве top-1/top-2 вызывается GPT-OSS 120B |
| `cascade_cosine` | Отдельный вариант: вызов LLM при низкой максимальной cosine similarity |

Реранкер BERT возвращает сырые logits, без sigmoid. LLM получает кандидатов в исходном dense-порядке; этот же вызов используется в полном LLM-режиме и каскадах. Во всех режимах GPT-OSS 20B получает первые пять документов с одинаковым промптом и ограничением длины.

## Установка

Нужен Python 3.11 или новее.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env
```

В `.env` вписать `GROQ_API_KEY`. Он нужен для LLM-реранжирования и генерации ответов. Для подготовки данных, dense и BERT ключ не нужен.

Настройки находятся в `config.toml`. `device` и `batch_size` можно менять в любой момент (например, `cuda` или `mps`): они влияют только на скорость, и запуск продолжается в той же папке `run_dir`. Поиск `retrieve` лучше посчитать один раз на одном компьютере и передать `candidates.jsonl` второму: на CPU и GPU эмбеддинги чуть различаются, а `candidates.jsonl` должен быть общим. Любая другая настройка при изменении требует нового `run_dir`: настройки сохраняются рядом с результатами, смешивать результаты разных конфигураций команда не позволяет. Версии Python и библиотек сохраняются в `environment.json`.

Тесты (без сети и без обращений к API): `pip install -e ".[dev]"`, затем `pytest`.

## Запуск

```bash
rerank prepare
rerank retrieve

rerank run --split validation --method bert
rerank run --split validation --method llm --allow-api
rerank tune

rerank run --split test --method all --answers --allow-api
rerank evaluate --split test --method all --answers
```

Всё, что может обращаться к API (режимы `llm`, `cascade_*`, `all` и любой запуск с `--answers`), требует флага `--allow-api` (или переменной окружения `RERANK_ALLOW_API=1`). Флаг означает: «я проверил в консоли Groq, что аккаунт на бесплатном тарифе и к нему не привязана карта». Код сам тариф определить не может.

Если LLM вернула неполный ответ или список, который не является перестановкой, запрос повторяется один раз с другими параметрами. Если и повтор не удался, берётся порядок BERT (а если его нет, порядок поиска), запрос помечается `llm_failed`, а затраченные токены всё равно считаются. Для ответов генератора то же самое: при неудаче ответ пустой и помечен `answer_failed`. Доля таких сбоев выводится в `evaluate` и сохраняется в `*.metrics.jsonl`. Если дневная квота исчерпана, прогон останавливается и продолжается позже той же командой.

Если команду запустить раньше, чем готовы её входные файлы (например, `tune` до `prepare`), она сообщит, какой шаг нужно сделать первым.

Без `--answers` выполняется только ранжирование. Генерацию можно добавить позднее, повторив ту же команду с `--answers`: готовые ранжирования сохранятся. `evaluate` без этого флага считает только поиск и расход реранжирования. Для отдельного режима вместо `all` указать его имя. Каскадам нужны завершённый BERT-прогон для выбранного split и сохранённые пороги.

Другой файл настроек:

```bash
rerank --config another.toml prepare
```

`prepare` фиксирует 100 validation- и 300 test-запросов с seed 42. В исходной разметке HotpotQA несколько вопросов указывают опорное предложение, которого нет в абзаце (в используемых ревизиях таких три). Они пропускаются, их id печатаются и записываются в `skipped_queries.json`. Выборка равномерно распределяется между существующими группами `(level, type)`. Исходные splits BEIR сохраняются: `validation` берётся из BEIR `dev`, а BEIR `test` соответствует открытой HotpotQA `validation`. В последней представлены hard-вопросы, поэтому там балансируется тип `bridge/comparison`. Ответы, сложности и предложения опорных фактов добавляются по id из [HotpotQA](https://huggingface.co/datasets/hotpotqa/hotpot_qa); qrels и корпус взяты из [BEIR](https://huggingface.co/datasets/BeIR/hotpotqa). Distractor-контексты служат только источником разметки опорных предложений; поиск идёт по полному корпусу BEIR.

Первый `retrieve` кодирует все 5,23 млн документов. Эмбеддинги сохраняются порциями, поиск точный по cosine similarity. Только кэш float32-эмбеддингов занимает около 16 ГБ; дополнительно скачиваются корпус и разметка. После прерывания готовые порции используются повторно. Top-20 сохраняется один раз для обоих splits, все режимы читают этот файл.

## Пороги и метрики

`tune` перебирает пороги только на validation. Для каждого порога берётся LLM-порядок у неуверенных запросов, BERT-порядок у остальных. Выбирается вариант с минимальным расходом токенов, у которого средний nDCG@10 отстаёт от полного LLM не более чем на `ndcg_tolerance` (по умолчанию 0,02 абсолютных пункта). Это параметр эксперимента, а не доказательство близости качества. Пороги сохраняются в `thresholds.json` и повторной командой не меняются; test при выборе порогов не читается.

Считаются nDCG@10, Recall@20, MRR@10, полнота опорных фактов в top-5, доля вызовов LLM и токены на запрос. При `--answers` добавляются EM, token-level F1 и отдельный расход генератора. EM/F1 следуют [официальной оценке HotpotQA](https://github.com/hotpotqa/hotpot/blob/master/hotpot_evaluate_v1.py), включая особое правило для yes/no/noanswer.

Опорный факт считается покрытым, если совпадает название документа и полное опорное предложение присутствует в фактически переданном генератору тексте после обрезки. Это полнота доступных свидетельств, а не оценка того, использовал ли их генератор.

Для разностей каждого режима с полным LLM и с BERT (если эти режимы выбраны) считаются парные bootstrap-интервалы 95% по запросам; в `{split}.bootstrap.csv` колонка `reference` говорит, с чем сравнение. По умолчанию 2000 повторов с фиксированным seed. Оценка выполняется только после завершения всех выбранных режимов на одной выборке.

## Файлы

По умолчанию результаты находятся в `runs/main/`:

- `validation.jsonl`, `test.jsonl`, `sample_counts.json`, `skipped_queries.json` — вопросы, ответы, qrels, опорные факты, состав выборки и пропущенные вопросы с битой разметкой;
- `candidates.jsonl` — общие top-20 с текстами и cosine similarity;
- `{split}.{method}.jsonl` — порядок документов, контекст, расход API и ответы;
- `validation.gap.csv`, `validation.cosine.csv`, `thresholds.json` — кривые выбора порога и зафиксированные значения;
- `{split}.metrics.jsonl`, `{split}.summary.csv`, `{split}.summary.json`, `{split}.bootstrap.csv` — метрики по вопросам, средние и интервалы разностей.

Прогоны пишутся по одному запросу. При повторном запуске готовые записи пропускаются; если ответ добавляется позднее, в JSONL появляется новая запись того же id, при чтении используется последняя.

`data/api.jsonl` содержит исходные ответы API, фактические input/output/total tokens, время вызова и ключ кэша. В сравнении режимов учитывается расход сохранённого ответа для каждого режима: это расход такого отдельного прогона. Реальный суммарный расход выполненных API-вызовов хранится в `data/api.jsonl`; использование кэша не добавляет туда новых записей.

Локальный бюджет считается отдельно для каждой модели за последние 24 часа. Перед вызовом резервируется оценка входных токенов и максимальный выход; при нехватке бюджета команда останавливается. Между вызовами выдерживается пауза по RPM/TPM. Оценка входа использует `o200k_harmony` и запас на служебные токены; фактический расход берётся из API. Значения в конфигурации соответствуют опубликованным [бесплатным лимитам Groq](https://console.groq.com/docs/rate-limits), но их нужно сверить с лимитами своего аккаунта. Ошибка API останавливает прогон, готовые результаты сохраняются; после восстановления доступа запускается та же команда.

Использовать ключ бесплатного плана. Автоматического перехода на платный тариф в коде нет, но и определить тариф по ключу код не может: поэтому команды с обращением к API запускаются только с `--allow-api`. Если бесплатный доступ требует карту, по плану этот сервис не использовать. Денежная стоимость здесь не рассчитывается.

План эксперимента лежит в `PLAN.md`, дополнения к нему (контрольные сравнения, пошаговый пример, список работ для сравнения) в `PLAN_ADDITIONS.md`.

`data/`, `runs/`, `.env` и `.venv/` исключены из Git.
